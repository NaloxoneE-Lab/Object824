## 待决（需要用户）

1. **dsh-TUI 是否安装**。tui 形态的发现与委托（§21.3、§21.5 的 `{pid, terminal:true}`）
   需要那个应用在机器上。按文档里的包名实现等于编造证据——包名、安装路径、`restart.log`
   的格式都该以真机为准。选项：
   - `npm i -g dsh-tui`（或 Windows 安装包），我按真机实现；
   - 或者只做"检测到未安装 → 明确告知"，不猜路径。

2. **desktop 形态的 start/stop 语义**。`o824 start` 对桌面端意味着"启动那个 GUI"，
   而 `desktop` profile 只能有一个实例在跑（会与用户自己的那一个冲突）。
   要不要做、以什么语义做（"如果没有在跑就启动，在跑就报告"？），需要一句话决定。

3. **Release 资产未上传**。`v0.1.2` 的 tag 与三个资产（`o824-mock-0.1.2.tgz`、
   `o824-mock.exe`、`SHA256SUMS`）当时说好由你在网页上传，目前仍未做，
   所以 README 里的安装 URL 还是 404。`o824-sdk` 的 tarball 同样还没发布。

4. **npm 公共 registry**（可选）。目前只有 GitHub Release 的 tarball；
   `npx o824-mock` 这种零安装路径要等发布到 registry。

## 不阻塞的已知缺口

- `o824 status` 只报**本内核启动过的**进程。扫描"端口上有监听但不在记录里"的通用残留
  没有做：没有命令行指纹的话，任何 node 监听器都会变成噪音，而拿命令行要读 PEB。
- 桌面端的 F11 判据依赖 asar 里的版本；asar 解析失败时该形态不参与漂移比较（已有注释）。


## 独立评审（2026-11-03）

P2-1 的进程控制代码经一次独立评审（1 Critical / 11 Important / 7 Minor / 6 处"测试通过但证明不了东西"）。
Critial 与 Important 全部修复，判据见提交 `651204a`：

| 编号 | 问题 | 修法 |
|---|---|---|
| C1 | 中断的 `start` 留下**无记录的活服务器**，之后任何 o824 命令都停不掉它 | 记录在 pid 存在的那一刻就写，就绪只更新端口；启动失败删掉临时记录；拿不到创建时间就拒绝启动 |
| I1 | `stop` 对已死的实例永远拒绝（与 `stop --all` 行为矛盾） | 区分三态：进程没了=成功并清记录；pid 还在但不是我们的=拒绝并保留；是我们的=停 |
| I2 | 并发守卫按**标签**而不是 home，且没有加锁 | 守卫变成"状态 + home"的纯函数；`start`/`stop` 取机器锁 |
| I4 | 只听 IPv4，绑在 IPv6 上的服务被当成空闲端口 | 同时读 AF_INET 与 AF_INET6 |
| I5 | `--public-url` 时端口被记成 0，之后所有端口判断都在问端口 0 | 端口是 `Option`，未知就是未知 |
| I9 | `E_CONCURRENT_INSTANCE` 不存在；`E_PORT_IN_USE` 落到退出码 8 | 补上错误码；两者都映射到 5（机器状态冲突） |

Minor 里修了三条明显是"错"的：桌面端并发警告只在默认 home 时发（临时 home 与它不共享会话）；
`status` 只在实例活着时显示 URL；`stop --all` 有拒绝时不再返回 0。

**未修的 Minor 记账**：`logs --tail` 非法值静默取 40；`logs` 整文件读入内存；旧日志不清理；
`stop` 只有 TerminateProcess（无优雅退出、无 force/tree 选项）；`wait_for_ready` 用 `read_to_string`
（一个非 UTF-8 字节就让就绪永远观测不到）。

**仍有一处测试只在有 DSH 的机器上跑**：`webform` 的真实起停用例在 CI 上跳过，所以 C1 那类
"实机才有"的缺陷，CI 绿不等于它不存在。
