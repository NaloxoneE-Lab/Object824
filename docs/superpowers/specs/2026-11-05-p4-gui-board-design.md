# P4 扩展：启动器窗口改成"发行版板"

> 2026-11-05。用户给了两张参考图（启动器主界面、点击右下圆钮后的菜单、设置对话框），
> 要求把 `apps/o824-gui` 的外观改成那样（背景后来改为直接用启动器的主题图，见 §2），
> logo 先用图里的，左侧三个
> 图标做成切换不同 DSH 发行版。用户明确说"先睡觉了，你直接做"，所以本文不是事前审批
> 稿，而是**事后记录**：做了什么、为什么这样做、哪些还没验证。

## 1. 要解决的问题

P3 的窗口是一个 880×640 的"体检报告"：左边安装列表、右边说明、底下状态。它把
§20 的三条首次使用路径说清楚了，但读起来像一个诊断工具，不像一个启动器。用户要的是
参考图那种"一块板"：左栏是发行版、主区是画面、右下是唯一的主按钮，其余东西收进弹层。

P4（安装器、清单签名、自更新）已经落地，这个改版算 P4 的界面扩展：窗口是发布物的一部分，
自更新的入口、关于页、设置页都在这一版里有了实体。

## 2. 不做什么

- **背景直接用启动器自己的主题图**。参考图就是本机的 Hypergryph Launcher 1.6.0；它的
  Endfield 主视觉（2324×1392，已含网格、黄块和 ENDFIELD 水印）在 `Games.exe` 的 Qt 资源
  里，取出来放进 `dist/assets/background.webp`。三个槽位也用启动器的
  `res/icons/{endfield,arknights,popucom}.ico`（256×256），不再用截图裁的小图。
  版权上这些是鹰角的素材，只为本机对齐，不随发布包分发（见 P4-GUI-BOARD 的说明）。
- **不代管账号**。参考图的"登录"在 O824 里没有对应物（DSH 的登录发生在 DSH 内），
  那个位置改成"检查更新"，接 P4 的 `update --fetch`。
- **不静默安装更新**。设置里的"更新"一项只自动**检查/下载并核对**，安装前仍然询问
  （§7.8、§20.3）。参考图的"开启静默更新"文案据此改写。
- **不新增内核能力**。窗口仍然只调用已有的 `discover`/`doctor`/`plan`/`apply`/
  `form_action`/`update`；三个发行版的切换是窗口自己的选择，不是新的内核状态机。

## 3. 三个发行版 = desktop / web / tui

用户确认"发行版"就是 §21 的三种受管形态。本机正好三个安装各一种（web 0.2.1-rc.5、
tui 0.18.0、desktop 0.2.1-rc.3），所以左栏三个槽位是真实数据，不是装饰：

- 每个槽位显示该形态的**第一个**安装；同形态有多个时，点底部"全部安装"选具体一个。
- 槽位角标：灰=已安装但本次窗口还没检查、绿=检查过且没问题、橙=检查过且有问题、
  暗灰=未安装（图变灰）。
- 选中哪个，主区就显示哪个的版本、内核给的那句话和下一步按钮。
- 未安装的形态也能选中：主区说"<名字>还没有安装"，主按钮变成"安装 DeepSeek Harness"，
  打开安装引导（不代装，§22）。

## 5. 信息架构

| 参考图控件 | O824 里的功能 | 判据 |
|---|---|---|
| 登录 | 检查更新 | 调 `update_check`；有更新时胶囊上出现黄点 |
| 齿轮 | 设置 | 启动器设置 / 关于两页 |
| — / × | 最小化 / 关闭 | 关闭按"最小化到托盘"设置决定 hide 还是 quit；第一次关窗先解释 |
| 三个游戏图标 | desktop / web / tui 切换 | 选中即诊断该安装，主区换成它的句子 |
| 底部网格 | 全部安装 | 列出 discover 的全部结果，点一条切过去 |
| 开始游戏 | 主按钮 | 执行内核给的 `action`：start / repair / install |
| 右下 ⊕（菜单） | 启动器设置 / 创建桌面快捷方式 / 完整性检查 / 清理更新缓存 | 与参考图四项一一对应 |
| DirectX 11 启动 | 启动后自动体检 | 启动成功后等 1.6s 重新诊断一次 |
| 设置：开机自动启动 | 开机自动启动 | HKCU\...\Run\O824，写失败会回滚开关 |
| 设置：开启静默更新 | 自动检查更新 | 启动时静默 `update_check`；安装仍要确认 |
| 设置：最小化到托盘 | 最小化到托盘 | 默认开；托盘不可用时禁用并说明 |

"完整性检查"打开详情弹层（诊断结果卡片）；"清理更新缓存"删 `%LOCALAPPDATA%\o824\staged`。
"创建桌面快捷方式"用 WScript.Shell 写 `.lnk`（手写 .lnk 格式不值得）。

## 6. 文案

参考图的文案是游戏的，不能照抄。新增的**窗口家具**全部进 `o824-present` 的新模块
`chrome.rs`（`Chrome` 结构 + `chrome(locale)`）：约 70 条，中英各一份，和内核句子走同一套
`every_key_exists_in_both_languages` / `no_catalog_string_contains_jargon` 测试。

- 机器状态的句子仍然只由内核产出（`checking` / `summarize` / `diagnose` / plan）。
- 窗口自己的标签（设置、更新、发行版名……）由 `chrome` 命令一次取回，前端不硬编码。
- 语言检测改成 **Windows UI 语言优先**（`GetUserDefaultUILanguage`），`LANG` 只做兜底：
  本机 `LANG` 为空，旧逻辑会让中文 Windows 显示英文窗口。`O824_LOCALE` 可强制。
- 模板用 `{version}`/`{name}` 占位，不做前后拼接。

## 7. 窗口技术决定

- **无边框 + 透明 + 固定尺寸**。圆角和"板"的边界由 CSS 画；`GetWindowRect` 比 DWM 的
  可见边界大 8px（阴影/不可见边框），这不是内容留白——截图脚本改用
  `DWMWA_EXTENDED_FRAME_BOUNDS`。
- **拖动**：`data-tauri-drag-region` 放在 rail、stage、art 上；按钮不在拖动区。
- **一个 WebView2 数据目录**。旧的 `prepare_webview_data()` 会选中
  `%LOCALAPPDATA%\O824-webview2`（该目录存在但不可写），而 builder 又传了另一个目录，
  结果 `CreateCoreWebView2Controller` 报 `0x800700AA`（"请求的资源在使用中"）。
  现在只选一次、写探针验证可写、env 和 builder 用同一个路径。这是本次改版挖出来的真 bug。
- **内核查找**从 4 层加到 6 层，开发布局（`apps/o824-gui/target/release` →
  `o824-rs/target/release`）下删掉 beside 副本也不会退化成 `kernel=o824`。
- **测试钩子**：`O824_GUI_QUERY` 追加任意 query；`O824_HOME`/`O824_DATA` 让 GUI 能指向
  实验室树（`f01/app`、`f01/home`、`f01/data`）；新增 `?close=1`、`?kind=web` 等状态。

## 8. 预计会被改的地方

1. ~~背景插图~~ **已做**：用 `Games.exe` 里提取的 Endfield 主题图。发布前若要规避版权，
   把 `dist/assets/background.webp` 与三个 `tab-*.png` 换成自有素材或删掉，窗口会回落到
   `--stage` 灰底。
2. **三个槽位的图**：现在是从参考图裁的占位（`tab-desktop.png` 等），发布前应换成
   自己画的或官方素材——参考图的角色图是第三方版权物，仅作本地视觉参考。
3. **LOGO**：同样裁自参考图（Endfield 的标记），发布前同样需要替换或确认授权。
4. **尺寸**：窗口写死 1180×648（参考图 1583×869 的等比）；如果用户屏幕更大，可以做成按比例缩放（viewport 单位）。
5. **快捷键**：目前只有 Esc/Enter 的默认行为，没有全局快捷键。
