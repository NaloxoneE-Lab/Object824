# `o824-sdk`（TypeScript）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个薄客户端，把 §7.5 第二层的七件事做完：分帧、请求/响应关联、事件回调、取消传播、进程退出检测与重启提示、能力协商、协议类型。**绝不**替用户确认、绝不重试变更类请求。

**Architecture:** 纯 Node（无运行时依赖）。`frames.ts` 是 Content-Length 编解码；`client.ts` 管一个子进程：写帧、按 id 关联、把 `op.state`/`op.progress`/`op.result` 变成事件；`protocol.ts` 是线格式的类型。测试用 `packages/o824-mock` 当服务器——它是**真实的帧格式**，不装 DSH 也能验。

**Tech Stack:** TypeScript（devDependency，编译成 ESM + `.d.ts`）、`node:test`、`node:child_process`。

**Spec:** `docs/design/2026-10-28-dsh-launcher-design.md` §7.5（第二层的"必须做/绝不做"）、§19.1–19.2（帧与作业事件）

## Global Constraints

- **运行时零依赖**；`typescript` 只在 devDependencies。
- 编译产物入库与否：**不入库**（`dist/` 进 .gitignore），与 mock 包同一个理由——产物会与源码漂移。
- 错误**原样抛**：`Code` / `message` / `data`，绝不改写成"友好文案"。
- 变更类请求（`o824.apply`）**不自动重试**。
- 语言：ESM（`"type": "module"`），Node ≥ 20。
- 类型先手写，并在测试里用 `spec/transcripts/*.jsonl` 做**契约测试**（每条真实报文都能落进类型）；由 JSON Schema 生成是 P2 的事，计划里记明。

## 自检

- §7.5 的七件"必须做"逐条对应到 Task 1（分帧、类型）、Task 2（关联、事件、退出）、Task 3（取消、能力协商）。
- "绝不做"三条：确认由调用方做（SDK 不提供 confirm）；`apply` 不重试（Task 2 的测试里断言重试需要显式再调）；错误原样抛（Task 2 的 `-32601` 用例）。
- 已知缺口，写进 README 而不是藏着：内核还没有 `kernel --stdio` 子命令，所以 `connect()` 必须显式给命令；mock 是当前可用的服务器。
